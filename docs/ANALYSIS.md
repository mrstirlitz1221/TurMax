# TurMax — анализ дипломной работы и проект реализации

Документ составлен по главам 1 и 2 дипломной работы («Анализ предметной области…» и «Проектирование веб-системы „ТурМакс“») и дополнительным требованиям заказчика (ASP.NET Core + SQL Server + Next.js, визуальный уровень портала visittheusa.com).

## 1. Цель проекта

Из п. 1.5: *создание веб-ориентированной системы «ТурМакс», обеспечивающей поиск, составление, сравнение и бронирование туристических маршрутов по Кыргызстану и автоматизирующей взаимодействие туристов и поставщиков туристических услуг.*

Ключевая идея диплома (модель «как должно быть», рис. 1.2): этапы «поиск информации → выбор → обращение к оператору → согласование цены» выполняются в одном приложении. Турист выбирает готовый тур или собирает маршрут на карте, сразу видит ориентировочную смету и отправляет заявку; оператор подтверждает её в кабинете.

Дополнительно, по ТЗ заказчика, система оформляется как вдохновляющий туристический портал: направления, достопримечательности, категории путешествий, журнал статей, интерактивная карта.

## 4. Нефункциональные требования (п. 1.5, 2.9)

- Безопасность: хеш паролей с солью (в дипломе — Argon2id; в .NET используется `PasswordHasher` ASP.NET Core Identity — PBKDF2-HMAC-SHA512, 100 000 итераций, см. раздел 7), роли, проверка владения объектом в сервисе, UUID-идентификаторы, access-токен 15 мин, refresh-токен 30 дней в HttpOnly-cookie с хешем в БД, ограничение частоты входа, единый формат ошибок `statusCode/error/message`, журнал аудита, секреты вне репозитория.
- Производительность: индексы под каталог и заявки, пагинация, оптимизация изображений через `next/image`.
- Совместимость: современные браузеры, экраны от 360 px.
- Сопровождаемость: модульная структура, Swagger/OpenAPI, автоматические тесты ключевой логики (расчёт сметы, переходы статусов).

## 5. Основные сущности (табл. 2.3 + портал)

Из диплома: `users`, `operators`, `regions`, `poi`, `tours`, `tour_points`, `departures`, `services`, `user_routes`, `route_points`, `bookings`, `booking_history`, `reviews`, `favorites`, служебные `photos`, `audit_log`, refresh-токены.

Добавлено для портала (ТЗ заказчика): `destinations` (направления — Иссык-Куль, Каракол…), `categories` (категории путешествий = «тип тура» из FR-01), `articles` (журнал), `notifications`.

Ключевые ограничения из диплома, перенесённые в SQL Server:
- `bookings`: `CHECK ((DepartureId IS NULL) <> (RouteId IS NULL))` — заявка ссылается либо на выезд, либо на маршрут (аналог `num_nonnulls(...) = 1`);
- `bookings.Participants BETWEEN 1 AND 50`;
- уникальные индексы `users(Email)`, `reviews(BookingId)`;
- индексы `tours(RegionId, Status)`, `bookings(OperatorId, Status)`.

## 6. Архитектура

Модульный монолит (п. 2.1), трёхуровневая схема: клиент (Next.js / React / TypeScript) → REST API (ASP.NET Core 8) → СУБД (SQL Server).

```
TurMax/
├── backend/
│   ├── TurMax.Api/            ASP.NET Core Web API (.NET 8)
│   │   ├── Controllers/       HTTP-слой: валидация DTO, роли
│   │   ├── Services/          бизнес-логика: Pricing, Routing, Bookings, Auth…
│   │   ├── Data/              DbContext, конфигурации EF Core, миграции, сид
│   │   ├── Entities/          сущности предметной области
│   │   ├── Dtos/              объекты передачи данных
│   │   └── Infrastructure/    JWT, обработка ошибок, аудит
│   └── TurMax.Tests/          xUnit: расчёт сметы, состояния заявки
├── frontend/                  Next.js (App Router, TypeScript)
└── docs/
```

Репозитории как отдельный слой не выделяются: `DbContext` EF Core уже реализует шаблоны «Репозиторий» и «Единица работы», лишняя обёртка не добавляет ценности (п. «Не усложняй архитектуру»). Правило диплома «модуль не лезет в чужие таблицы» соблюдается через сервисы: `BookingService` получает смету только через `PricingService`.

Маршрутизация (п. 2.2, 2.4): интерфейс `IRoutingProvider` («Стратегия») с реализациями `OsrmRoutingProvider` (адрес OSRM в настройках) и `HaversineRoutingProvider` — резервная оценка по прямой × 1,3 с пометкой «приблизительно» (замена PostGIS `ST_Distance`).

Карта: Leaflet + OpenStreetMap (табл. 1.5), адрес сервера тайлов вынесен в настройки (п. 2.2).

## 7. Расхождения с текстом диплома

Технологии в главах 1–2 и требования заказчика к реализации различаются. Реализация выполнена по требованиям заказчика; в тексте диплома нужно будет обновить:

| В дипломе | В реализации | Где править |
|---|---|---|
| Node.js / NestJS, TypeORM | ASP.NET Core 8, EF Core 8 | табл. 1.6, п. 2.1, 2.2, рис. 2.1 |
| PostgreSQL + PostGIS, `geography`, `ST_DWithin` | SQL Server; координаты `decimal(9,6)`, расстояния — формула гаверсинуса в сервисе | табл. 1.6, п. 2.3 |
| React SPA | Next.js (React + TypeScript) с серверным рендерингом — лучше для SEO | табл. 1.6 |
| Argon2id | PBKDF2 (`PasswordHasher` ASP.NET Core) | табл. 2.9 |
| `pg_dump` | `BACKUP DATABASE` SQL Server | п. 2.2 |
| jsonb ru/ky/en | FR-21 не реализован в первой версии | п. 2.3 |

## 8. Структура страниц

Публичная часть: `/` главная · `/destinations`, `/destinations/[slug]` · `/attractions/[slug]` · `/tours` (каталог-маршруты с фильтрами), `/tours/[slug]` · `/categories/[slug]` · `/map` · `/journal`, `/journal/[slug]` · `/search` · `/login`, `/register`.

Кабинеты: `/planner` (конструктор), `/account` (маршруты, заявки, избранное, уведомления) · `/operator` (профиль, туры, выезды, тарифы, заявки, отзывы, статистика) · `/admin` (пользователи, операторы, модерация туров и отзывов, справочники, статьи, журнал).
